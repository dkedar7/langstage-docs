**Stage:** the terminal, `langstage-cli`. **Shows:** an agent that investigates with
read-only tools, the CLI's approval menu, and a change that only happens once you
approve it.

On-call work is mostly searching: when did it start, what changed, what does the
evidence say. This example gives an agent the logs, the deploy history and the config,
lets it search freely, and makes it ask before it touches production.

## What happens

1. Inside the on-call workspace, you start `langstage-cli --agent ../agent.py:graph`
   and say: "The API started throwing 503s around 2pm. Find the root cause and fix
   it."
2. The agent lists the workspace, then searches instead of reading whole files. It
   finds where the 503s and `QueuePool` timeouts begin in the API log, lines them up
   with the deploy history, and reads the release diff and the config.
3. The cause: deploy v2.8.0 at 14:01:55 shipped a "tidy db config" change that cut
   `pool_size` from 20 to 5 and `max_overflow` from 10 to 0. The first pool timeout
   is at 14:02:52, and the errors climb from there.
4. It proposes restoring the pool settings with `apply_config_change`, which pauses.
   The CLI shows the exact change and the agent's reason in its approval menu. You
   approve.
5. The change is applied, the agent writes an incident note with the cause, the fix
   and a follow-up, and you check the result with `grep` before you leave.

## The agent

172 lines in [`gallery/incident-investigator/agent.py`](https://github.com/dkedar7/langstage-docs/blob/main/gallery/incident-investigator/agent.py):

- **Read-only investigation tools:** `list_files`, `search` (a regular expression with
  a match count, the first and last match, and line numbers) and `read_file` (a range
  of lines). They're built for large logs: the agent searches, then reads only what it
  needs.
- **One tool that changes things.** `apply_config_change` calls LangGraph's
  `interrupt()` before it writes anything, with the change in LangChain's
  human-in-the-loop shape. The CLI turns that into its approval menu: approve all,
  reject all, or a custom decision such as an edited value.
- **`write_incident_note`**, so the investigation leaves a record.

## Run it yourself

<!-- snippet: check -->
```bash
git clone https://github.com/dkedar7/langstage-docs
cd langstage-docs/gallery/incident-investigator/workspace
pip install langstage-cli langchain-anthropic
export ANTHROPIC_API_KEY=...
langstage-cli --agent ../agent.py:graph
```

To use OpenRouter instead, set `OPENROUTER_API_KEY` and `pip install langchain-openai`.
The same agent runs anywhere LangStage does; in a script or CI job, a paused approval
exits with code `2`, so a pipeline can tell "waiting for a human" from "failed" (see
[Exit codes](../reference/exit-codes.md)).

The logs are synthetic, generated by
[`make_logs.py`](https://github.com/dkedar7/langstage-docs/blob/main/gallery/incident-investigator/make_logs.py)
from a fixed seed: about 2,300 lines of API log and a database log, with the deploy in
the middle. Nothing in them names the cause; the agent has to connect the timeline,
the errors and the diff.
